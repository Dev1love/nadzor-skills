# Аудит безопасности `demo-shop` перед релизом

Проверял на локальном стенде (порт 3917, отдельная БД `/tmp/sa-audit/audit.db`, рабочий `shop.db` не трогал). Свежий субагент искал, я перепроверил каждую критичную находку собственным запросом. Код не менял, свой процесс остановил по PID. **Выпускать нельзя** — четыре критичные дыры.

## Критично

**1 · IDOR: чужой заказ по id** — `src/routes/orders.js:97` `SELECT * FROM orders WHERE id = ?`, нет проверки владельца.
Сценарий: любой вошедший перебирает id и читает адрес, телефон, состав чужих заказов.
Фикс: `WHERE id = ? AND user_id = ?` с `req.user.id` (как уже в `/receipt:104`).
Доказано: `curl /api/orders/2 -H "Bearer <токен Боба>"` → `200` + `"address":"Alice street 1","phone":"+79990000001"` (чужой заказ Алисы). Тот же токен на `/receipt` → `404`. После фикса ожидается `404`.

**2 · Mass assignment → захват роли admin** — `src/routes/users.js:14-18`, ключи тела идут прямо в `UPDATE users SET ...`.
Сценарий: покупатель шлёт `{"role":"admin"}` и получает админку (плюс можно переписать `password_hash`, `email`).
Фикс: whitelist `['name','phone']`, имена колонок только из кода.
Доказано: `PATCH /api/users/me {"role":"admin"}` Бобом → роль `admin`; затем `GET /api/admin/orders` было `403`, стало `200` со списком всех заказов.

**3 · SQL-инъекция через имя колонки** — тот же `src/routes/users.js:17`, ключ тела подставляется в SQL как есть.
Сценарий: ключ-подзапрос читает чужие данные/токены сессий в своё поле.
Фикс: тот же whitelist — имена колонок никогда из ввода.
Доказано: `PATCH /me` с ключом `"phone = (SELECT email||char(32)||substr(password_hash,1,12) FROM users WHERE id=1), name"` → в `phone` Алисы оказались email и часть хеша админа. После фикса — `400`.

**4 · Вебхук оплаты без подписи и без сверки суммы** — `src/routes/webhooks.js:7-11`; `verifySignature` из `src/lib/paygate.js` **нигде не вызывается** (`grep` по `src` пусто).
Сценарий: кто угодно шлёт `{"orderId":N,"status":"succeeded"}` → заказ `paid` бесплатно; отменённый заказ тоже помечается оплаченным.
Фикс: `express.raw()` + проверка `X-PayGate-Signature` HMAC через `timingSafeEqual`; сверка суммы с `orders.total`; переход только `new→paid`; дедуп событий по UNIQUE.
Доказано: `POST /api/webhooks/payment {"orderId":2,"status":"succeeded"}` без подписи → `200`, статус заказа `new`→`paid`. После фикса — `401` без подписи, `400` при неверной сумме.

## Высоко

**5 · Нет валидации `qty`/`productId` → подмена суммы и остатков** — `src/routes/orders.js:35-41`.
Доказано мной: `qty:-5` → `total:-1560` и остаток товара вырос до `51.5`; `qty:0.5` → дробная сумма; две строки по `qty:6` при остатке 9 → `201`, остаток ушёл в `-3` (пересортица обходит проверку остатка).
Фикс: `Number.isInteger(qty) && qty>0`, целочисленный `productId`, склейка одинаковых позиций, списание `UPDATE ... WHERE id=? AND stock>=?` с проверкой `changes`.

**6 · Ошибка вебхука проглатывается, провайдеру уходит 200** — `src/routes/webhooks.js:17-20`. Оплата теряется без ретрая. Фикс: при ошибке отвечать `5xx`. (Субагент: `orderId:999` → `200 {"received":true}`.)

**7 · Сессии: TTL 30 дней, нет logout, нет сброса при смене пароля** — `src/auth.js:5,24`. В коммите `37b7a8f` срок вырос с 1 часа до 30 дней. Украденный токен живёт месяц и неотзываем. Фикс: короткий TTL, `POST /api/logout` (DELETE из sessions), удаление сессий при смене пароля. (Проверено: `/api/logout` → `404`, grep по инвалидации пусто.)

## Средне

**8 · CSV-инъекция в админской выгрузке** — `src/routes/admin.js:23`, `email` не экранируется; на регистрации нет серверной валидации email. Доказано: регистрация с email `=2+5+cmd|calc` → эта формула в `/api/admin/orders.csv`, которую откроет бухгалтер. Фикс: экранировать `; " \n`, префиксовать `'` значения на `= + - @`, валидировать email.

**9 · Прочее (кратко):** лимит логина по `req.ip` без `trust proxy` — за прокси все делят один IP (блок всем) и успешные входы тоже считаются (`src/auth.js:55`); регистрация без лимита + блокирующий `scryptSync` → DoS; `sort=constructor` → `500` (нужен `Object.hasOwn`, `src/server.js:43`); нет заголовков безопасности (helmet), торчит `X-Powered-By`.
