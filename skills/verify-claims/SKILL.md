# Технадзор: проверка отчёта агента

## Суть
Не доверяем отчёту, проверяем факты. Каждое утверждение отчёта получает статус: **подтверждено** (команда и вывод), **опровергнуто** (команда и вывод), **не проверить** (почему). Сессия, которая писала код, свою работу не проверяет: запускать в новой сессии или через свежего субагента.

## Входные данные (собрать до начала)
1. **Отчёт агента.** Откуда, по порядку: что пользователь вставил в сообщение; описание PR (`gh pr view <N> --json body`); файл отчёта в репо (`*REPORT*.md`, `PR_DESCRIPTION.md`); последний коммит. Отчёта нет: спроси пользователя, не выдумывай.
2. **Задача.** Исходное описание задачи (трекер, файл задач, issue), не пересказ агента. Нет: спроси.
3. **Дифф.** `git diff <base>...HEAD` + незакоммиченное + неотслеживаемые файлы. Base: ветка, от которой ответвилась задача.

## Шаги
1. **Разложи отчёт на утверждения.** Каждое «сделал X», «исправил Y», «тесты проходят», «добавил проверку Z» отдельной строкой.
2. **Сверка с диффом.** Для каждого утверждения найди изменения, которые его реализуют (`file:line`). Затем обратное: изменения в диффе, которые в отчёте не упомянуты.
3. **«Тесты проходят».** Найди команду тестов, как в CI. Запусти сам, запиши: всего, прошло, упало, **пропущено**. Затем `git diff <base>...HEAD` по тестам: удалённые, `skip`/`only`/`todo`, ослабленные проверки, изменённые ожидания. «Проходят, потому что 3 теста выключены» = опровергнуто.
4. **«Исправил баг».** Схема «падает до, проходит после»: найди или напиши минимальный сценарий воспроизведения (тест или запрос). Проверь на base (`git worktree add <tmp> <base>` или `git stash -u && git checkout <base>`), потом на HEAD. Временные скрипты и worktree держи в `mktemp -d`, не рядом с репозиторием (рекурсивно не удаляй, папку чистит ОС). В конце вернуть ветку и stash, `git worktree remove <путь>`, `git status --short` в отчёт.
5. **«Добавил проверку / защиту».** Покажи, что она срабатывает: запрос, который должен быть отклонён, отклоняется. Код проверки без вызова не считается. Приложение поднимай на свободном порту (`PORT=0` или случайный) и убедись, что отвечает именно твой процесс; останавливай его по своему PID.
6. **Красные флаги** через субагента по шаблону ниже. Каждую находку проверить по `file:line`.
7. **Соответствие задаче.** Сравни требования из исходной задачи с реализацией, а не с тем, как агент её понял. Невыполненные требования и подмена требований отдельным списком.
8. **Вердикт** и отчёт.

## Шаблон промпта субагенту (красные флаги)
```
Ты технадзор. На языке пользователя. Код не меняй. Запускать тесты и локальные запросы можно: временные файлы и копии только в `mktemp -d` (системная временная папка, её чистит ОС; рекурсивно не удаляй, `rm -rf` агенту не нужен), свои процессы останавливай по PID. Ищешь в диффе то, что агенты делают, чтобы задача выглядела готовой.
Задача (исходная): <текст>. Дифф: `git -C <repo> diff <base>...HEAD` + незакоммиченное + новые файлы.
Ищи:
- проглоченные ошибки: пустой catch, catch только с логом, catch, который возвращает успех; провайдеру/клиенту уходит 200 при сбое;
- захардкоженные значения вместо логики, особенно совпадающие с ожиданиями тестов (функция возвращает константу, которую проверяет тест);
- заглушки, моки, фейковые данные, `if (test)` ветки в рабочем коде;
- TODO, FIXME, «временно», закомментированный код, `not implemented`;
- отключённые проверки: eslint-disable, @ts-ignore, `any` ради компиляции, `--no-verify`, ослабленные настройки линтера/типов/CI;
- тесты: удалены, skip/only, ослаблены ожидания в этом же изменении;
- изменения вне задачи: файлы и поведение, которые задача не просила менять (особенно авторизация, сроки сессий, конфиги, зависимости).
Каждая находка: file:line + цитата + почему это флаг. Без file:line не пиши.
ИТОГ (до 400 слов), по убыванию риска.
```

## Формат отчёта пользователю
1. **Вердикт:** принять / доработать / отклонить, одной строкой с главной причиной.
2. **Утверждения отчёта:** таблица `утверждение | статус (подтверждено / опровергнуто / частично / не проверить) | доказательство одной фразой (команда → результат или file:line)`. Статусы словами, без значков и эмодзи.
3. **Сделано, но не заявлено:** по строке на изменение, с `file:line`.
4. **Требования задачи, которые не выполнены:** по строке.
5. **Красные флаги:** только те, что не вошли в пункты выше: `file:line | что | риск`.
6. **Чистота:** одна строка: `git status --short` пуст, ветка та же.

Короткий отчёт: до ~400 слов, без вступлений и пересказа методики. Ячейка таблицы до ~15 слов. Больше 7 главных находок: остальные в «Ещё» по одной строке `file:line: что`. Подробные доказательства не вставлять целиком: одной фразой в ячейке, полностью по запросу («покажи доказательство к N»). Числа в вердикте (сколько опровергнуто) считать по таблице, а не по памяти.

Вердикт: «принять» только если нет опровергнутых утверждений и нет флагов уровня «проглоченная ошибка в деньгах/правах». Хоть одно опровергнутое утверждение о тестах или защите: «доработать» минимум.

## Частые ошибки
| Ошибка | Как правильно |
|---|---|
| Проверять в той же сессии, что писала код | Новая сессия или свежий субагент |
| «Тесты проходят» по выводу из отчёта | Запустить самому, посчитать пропущенные |
| Смотреть код проверки и считать, что она работает | Вызвать: запрос должен быть отклонён |
| Сверять с пересказом задачи агентом | Сверять с исходной задачей |
| Пропустить незаявленные изменения | Обратная сверка: дифф → отчёт |
| Оставить временные тесты и переключённую ветку | Удалить, вернуть, `git status --short` в отчёт |
