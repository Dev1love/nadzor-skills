# Технадзор: проверка отчёта агента

Отчёт агента это его план, а не факт. Каждое утверждение проверяем запуском или кодом. Запускать в новой сессии или свежим субагентом: сессия, которая писала код, себя не проверяет.

## Рамки
- Код не меняем. Временные файлы и worktree только в `mktemp -d`, рекурсивно не удаляем (папку чистит ОС).
- Зависимости только в окружение проекта: его docker, venv или установка по lock-файлу в копии. Не вышло: «не проверить», без обходов.
- Приложение поднимаем на свободном порту, проверяем, что отвечает наш процесс, останавливаем по своему PID. Прод и чужие адреса не трогаем.

## Вход
- **Отчёт агента:** из сообщения пользователя, описания PR, файла `*REPORT*.md` или последнего коммита. Нет отчёта: спросить, не выдумывать.
- **Исходная задача**, а не пересказ агента. Нет: спросить.
- **Дифф:** `git diff <base>...HEAD` + незакоммиченное + неотслеживаемые файлы.

## Шаги
1. Разложи отчёт на отдельные утверждения.
2. Для каждого найди реализацию в диффе (`file:line`). Потом обратная сверка: что изменено, но не заявлено.
3. **«Тесты проходят».** Запусти сам той же командой, что в CI. Посчитай пропущенные. По диффу проверь, не удалены ли и не ослаблены ли тесты. Проходят за счёт выключенных = опровергнуто.
4. **«Исправил».** Сценарий воспроизведения должен падать на base и проходить на HEAD.
5. **«Добавил защиту».** Вызови её: запрос, который должен быть отклонён, отклоняется. Код проверки без вызова не считается.
6. **Красные флаги** через субагента по шаблону ниже. Каждую находку перепроверь по `file:line`.
7. Сверь реализацию с исходной задачей, а не с тем, как агент её понял.

## Промпт субагенту
```
Ты технадзор, на языке пользователя. Код не меняй. Тесты и локальные запросы можно: временное в mktemp -d, зависимости только в окружение проекта.
Задача (исходная): <текст>. Дифф: git -C <repo> diff <base>...HEAD + незакоммиченное + новые файлы.
Найди в диффе то, что делает задачу похожей на готовую: проглоченные ошибки (в том числе ответ 200 при сбое), значения, подогнанные под ожидания тестов, заглушки и фейковые данные в рабочем коде, TODO и «временно», отключённые проверки линтера и типов, выключенные или ослабленные тесты, изменения вне задачи (особенно права, сессии, конфиги, зависимости).
Каждая находка: file:line, цитата, почему это флаг. Без file:line не пиши. До 400 слов, по убыванию риска.
```

## Отчёт
До ~400 слов, статусы словами, без значков.
1. **Вердикт:** принять / доработать / отклонить, с главной причиной. «Принять» только без опровергнутых утверждений и без флагов в деньгах и правах.
2. **Утверждения:** `утверждение | подтверждено / опровергнуто / частично / не проверить | доказательство одной фразой`.
3. **Сделано, но не заявлено:** по строке с `file:line`.
4. **Требования задачи, которые не выполнены.**
5. **Флаги**, не вошедшие выше.
6. **Чистота:** `git status --short` пуст, ветка та же.
7. **Передать** другому скиллу (`security-audit`, `test-auditor`, `dry-kiss-yagni-srp`, `leak-guard`): одной строкой, «нечего» тоже ответ.

Числа в вердикте считать по таблице. Подробные доказательства по запросу («покажи доказательство к N»).
