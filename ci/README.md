# Шлагбаум перед основной веткой

Робот проверяет каждый PR. Если что-то красное, PR нельзя слить, как бы агент ни старался.

| Проверка | Красное (блокирует) | Жёлтое (предупреждение) |
|---|---|---|
| Секреты в коммитах этого PR (gitleaks) | ключ, токен, пароль | |
| Тесты (`npm test`, `pytest` или `make test`) | хоть один упал | есть пропущенные; команды тестов нет |

## Подключить
1. Скопировать `ci/gate.sh` в проект (путь `ci/gate.sh`) и `ci/tech-check-gate.yml` в `.github/workflows/`.
2. В настройках репозитория сделать проверку обязательной: Settings → Branches → правило для `main` → Require status checks to pass → `tech-check-gate`.

Локально то же самое: `ci/gate.sh origin/main`.

## Чего здесь нет и почему
- **Старые утечки.** Смотрятся только коммиты этого PR. Секрет из старой истории лечится перевыпуском ключа, а не блокировкой всех будущих PR. Для истории есть `leak-guard`.
- **Ключи нестандартного формата.** gitleaks знает популярные форматы и общие шаблоны. Ключ вида `crm_live_...` он может не узнать. Поэтому перед выкладкой всё равно нужен `leak-guard`.
- **ИИ-ревью в CI.** Скиллы можно запускать и в CI, но агент с доступом к шеллу на коде из PR открывает дверь для prompt injection: текст в PR может попросить агента вывести ключ API. Если нужно, используйте официальный `anthropics/claude-code-action` с его ограничениями и только для PR из своего репозитория. Ревью скиллами надёжнее делать локально, до PR.
