# Демо: task-trail

**«Почему лимит 7000?»**

Лимит первого заказа был 5000 ₽, решение с причиной записано в задаче #10. Потом агент коммитом «quick fix» поднял его до 7000 и заодно поменял округление промокодов. Есть задача #15 «7000 только для проверенных клиентов», но коммит на неё не ссылается.

## Запуск
```bash
demos/run.sh task-trail              # интерактивно, для сцены
demos/run.sh task-trail --headless   # репетиция: печатает отчёт
```
Запрос к скиллу: `demos/task-trail/prompt.txt`. Пример готового отчёта: [`sample-report.md`](sample-report.md) (запасной вариант, если живой прогон не успеет).

## Что заложено
Этот файл в копию для скилла не попадает.

- Цепочка `строка → коммит → задача` рвётся на «quick fix»: задачи нет.
- Предыдущее значение 5000 объяснено в #10 (чарджбэки), это скилл должен найти.
- #15 похожа, но меняет лимит только проверенным, а коммит поднял всем: скилл не должен додумывать связь.
- Аудит: «quick fix» и «wip» без задачи, «quick fix» смешал два несвязанных изменения (лимит и округление промокода, второе противоречит #12).

## Чего ждать
Ответ «почему» со ссылками на каждое звено и честное «здесь цепочка рвётся». Черновики: сообщение коммита, комментарий в задачу.

## Что сказать
Через полгода причину помнит только история. Скилл находит её или честно говорит, что её нет.
