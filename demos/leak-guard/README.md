# Демо: leak-guard

**Лендинг: ключ CRM в браузере**

Лендинг с формой заявок. Разработчик закоммитил `.env` и следующим коммитом удалил. Агент «ускорил» отправку заявок в CRM прямо из браузера и добавил отладку.

## Запуск
```bash
demos/run.sh leak-guard              # интерактивно, для сцены
demos/run.sh leak-guard --headless   # репетиция: печатает отчёт
```
Запрос к скиллу: `demos/leak-guard/prompt.txt`. Пример готового отчёта: [`sample-report.md`](sample-report.md) (запасной вариант, если живой прогон не успеет).

## Что заложено
Этот файл в копию для скилла не попадает.

- Ключ CRM `crm_live_...` в `public/config.js`: виден любому посетителю.
- `.env` с ключом CRM и паролем почты остался в истории git, хотя файл удалён.
- `GET /api/debug` без входа отдаёт все заявки (имена, телефоны) и настройки CRM.
- Ловушка: `MAP_PUBLIC_KEY` публичный ключ карты, это не утечка. Скилл должен объяснить, при каком условии это нормально (ограничение по домену), а не записать в красное.
- Побочно реальное: кривой JSON в `POST /api/leads` роняет сервер целиком, у формы нет ограничения частоты.

## Чего ждать
Светофор для не разработчика: 3 красных; ключ карты в жёлтом или зелёном с условием «проверить ограничение по домену». «Перевыпустить ключ, а не просто удалить». В образце скилл честно пишет, что gitleaks формат этих ключей не знает и все три красных найдены вручную.
