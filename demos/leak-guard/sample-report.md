## Для разработчика
1. `public/config.js:3` и `public/app.js:10-14`: ключ `crm_live_…` уходит в браузер, и браузер сам отправляет данные клиента (имя, телефон) в `crm.example`. Ключ совпадает с тем, что лежал в удалённом `.env`. Нужно перевыпустить ключ, убрать его из `config.js` и отправлять заявку в CRM из `POST /api/leads` на сервере. Проверка: `curl -s localhost:$PORT/config.js | grep CRM` ничего не находит.
2. `src/server.js:30-33`: `GET /api/debug` без авторизации отдаёт `crmApiKey`, `smtpPassword` и весь массив `leads`. Я подтвердил это запуском с фейковыми секретами: ответ 200 со всеми полями. Эндпоинт нужно удалить. Проверка: `curl -s -o /dev/null -w '%{http_code}' localhost:$PORT/api/debug` возвращает 404.
3. Коммит `68213de` добавил `.env` с реальными `CRM_API_KEY` и `SMTP_PASSWORD`, коммит `346d08e` его удалил, но в истории значения остались. Нужно перевыпустить оба секрета, а затем по желанию очистить историю через `git filter-repo --path .env --invert-paths` и сделать force-push. Это делаете вы. Проверка: `git log --all -- .env` ничего не выводит.
4. `public/config.js:2`: `pk_map_…` по названию и комментарию публикуемый ключ. Он безопасен, только если в консоли провайдера карт включено ограничение по домену. Из репозитория это не проверить.

Важно: gitleaks на истории **ничего не нашёл**, потому что не знает формат этих ключей. Все три красные находки найдены вручную, и каждая подтверждена.
